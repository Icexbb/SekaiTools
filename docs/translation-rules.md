# 翻译检查配置

运行目录中的 `translation-rules.json` 控制翻译编辑页的自动替换和检查。修改后重启生效，文件缺失时使用内置默认值。构建、发布自动复制该文件。

## 并列检查项

`checks` 数组中的每个对象独立包含条件和反馈，按配置顺序执行；同一行可同时显示多项反馈。没有针对句尾、省略号或破折号的专用配置字段。

```json
{
  "id": "missing-end-punctuation",
  "enabled": true,
  "scope": "line",
  "conditions": [
    { "target": "text", "pattern": "[、，。？！~♪☆.—][）」』”]*$", "match": false }
  ],
  "feedback": { "message": "句尾缺少结束标点" }
}
```

- `id`：唯一标识，用于配置报错定位。
- `enabled`：是否启用，默认 `true`。
- `scope`：`line` 逐行检查，或 `content` 整段检查，默认 `line`。逐行检查沿用原行为：忽略空行、去除行尾空白。
- `conditions`：所有条件同时满足才反馈；需要“或”时可使用正则 `|`，或添加独立检查项。
- 条件 `target`：默认 `text`，即当前行或整段译文。也可匹配编辑器提供的 `originalLineCount`（原文行数）、`maxLineLength`（译文最大单行加权长度），数值作为十进制字符串参与匹配。未提供的指标不触发检查，即使 `match` 为 `false`。
- 条件 `pattern`：.NET 正则表达式。默认判断是否存在匹配；匹配整个值时使用 `^`、`$`。
- 条件 `match`：默认 `true`，匹配时满足；设为 `false` 表示不匹配时满足。
- `feedback.message`：提示文字，条件与反馈保存在同一个对象中。
- `feedback.tags`：可选反馈标签数组。`length` 会同时让编辑器行长指示变红；检查器不根据检查项 id 判断行为。

默认配置中的普通行长规则使用正则 `^(?:3[89]|[4-9][0-9]|[0-9]{3,})$` 表达大于 37，原文三行时使用另一并列检查项表达大于 45。行长仍使用原有加权计数。新增或修改规则时，应同步调整该对象的条件和提示文字。

## 自动替换

`replacements` 按数组顺序执行，每项为通用正则替换：

```json
{ "enabled": true, "pattern": "([A-Z]+)!", "replacement": "$1！" }
```

支持 `$1` 等捕获组引用；字面量 `$` 应写为 `$$`。空数组关闭所有替换。避免配置循环或不断增长的替换规则。检查在自动替换后执行。

JSON 中的反斜杠需要转义，例如字面问号的正则写为 `"\\?"`。所有正则在加载时校验并缓存，单次匹配或替换限制为 100 毫秒，避免复杂表达式长时间占用编辑线程。无效配置会报告错误，不应删除必填字段。

此版本采用 `checks` 数组及正则替换，替代旧版专用字段；旧配置应按新文件结构迁移。此配置仅用于翻译编辑器提示，不改变剧本条目／编号匹配，也不改变字幕导出的自动分句规则。
