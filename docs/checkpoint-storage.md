# 队列检查点分块存储

Windows 字幕队列通过 `IncrementalProgressStore` 保存进度；模型与算法仍位于 Core，文件协议在 Infrastructure 实现。旧版 `ProgressStore` 与已完成历史继续使用完整 JSON。

## 文件布局与提交顺序

任务主文件仍为 `SubtitleQueueProgress/<key>.json`，摘要字段仍位于根对象，历史列表无需加载分块即可读取视频路径及状态。已完成的对话、横幅和角标事件写入 `<key>.json.chunks/<SHA256>.json`，主文件对应位置只保存 `$chunk` 引用。未完成事件与匹配器状态仍直接保存于主文件。

时间码以 4096 项为一块写入同一目录，主文件 `Timecodes` 用 `$blocks` 列出有序块引用，读取后还原为原有完整时间码列表。旧文件中的直接时间码数组仍受支持。处理期只为支持增量快照的持久化实现提供不可变块，其他实现及公开捕获继续提供完整列表；追加时复用完整前缀，只复制尾块。已有时间码修正会使受影响及后续缓存失效，恢复或全量捕获清空缓存，不修改旧快照持有的块。

处理期检查点复用已经冻结的完成事件 DTO，使用弱引用关联其内容身份，避免重复序列化完成轨迹。普通全量捕获与编辑后保存不使用该身份缓存，防止复用旧编辑结果。

先将新增分块写入同目录临时文件、刷新数据并替换目标文件，最后才以相同方式提交主文件。主文件替换失败时原主文件仍可读取；此前写入但未被引用的块不改变原恢复结果。没有对过往分块进行就地修改或在保存中删除旧块，因此读取者不会因正在保存新一代检查点而失去旧引用。

## 读取与兼容

主文件包含 `CheckpointStorage: 1`，磁盘模型版本写为 `chunks1:<原模型版本>`。新读取器校验存储版本并恢复原模型版本，再交给 Core 检查素材及配置兼容性；旧程序会拒绝该模型版本，避免将分块引用误当作空事件。

没有存储标记的旧全量文件继续按旧格式读取，但不能包含分块引用。分块名称仅允许 64 位大写十六进制摘要；读取时检查 SHA256、完成标志、目录及文件重解析点，拒绝损坏、缺失或越界引用，不把不完整记录作为正常结果恢复。

队列扫描、历史按需加载与一次性恢复均通过同一读取入口。历史导出得到的仍是完整 `ProcessingState`，不向算法暴露文件引用。

## 清理

正常完成时先等待进度写入排空，再移除主文件及本任务摘要命名的块文件。一次性恢复先完整读入各任务，再消费主文件与块文件。只清理本任务块目录里的已知文件，不递归跟随目录联接；块清理失败会记录警告，不让已经读入的恢复任务因此丢失。

更多素材的磁盘中断恢复及多轮性能对照仍需继续验证。当前测试覆盖旧格式、完整状态往返、完成块复用、活动事件更新、编辑后保存、损坏和路径引用拒绝、提交失败保留旧状态、摘要按需加载与真实解码器恢复，以及时间码追加、变帧率、旧项修正后的块失效和恢复。
