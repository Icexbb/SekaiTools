# 队列检查点存储

Windows 字幕队列通过 `IncrementalProgressStore` 保存进度；模型与算法仍位于 Core，文件协议在 Infrastructure 实现。旧版 `ProgressStore` 与已完成历史继续使用完整 JSON。

## 文件布局与提交顺序

任务主文件仍为 `SubtitleQueueProgress/<key>.json`，摘要字段仍位于根对象，历史列表无需加载分块即可读取视频路径及状态。已完成的对话、横幅和角标事件按内容摘要标识，并与时间码块一起装入 `<key>.json.chunks/<包SHA256>.json`。主文件对应位置用 `$chunk` 指定载荷摘要、`$pack` 指定包摘要。每包目标约 1 MiB；单个载荷超出目标时保留独立内容文件，使用无 `$pack` 的引用，避免额外包装复制。未完成事件与匹配器状态仍直接保存于主文件。旧 v1 独立块也可继续使用无 `$pack` 的引用，不必重写。

时间码以 4096 项为一块写入同一目录，主文件 `Timecodes` 用 `$blocks` 列出有序块引用，读取后还原为原有完整时间码列表。旧文件中的直接时间码数组仍受支持。处理期只为支持增量快照的持久化实现提供不可变块，其他实现及公开捕获继续提供完整列表；追加时复用完整前缀，只复制尾块。已有时间码修正会使受影响及后续缓存失效，恢复或全量捕获清空缓存，不修改旧快照持有的块。

处理期检查点复用已经冻结的完成事件 DTO，使用弱引用关联其内容身份，避免重复序列化完成轨迹。普通全量捕获与编辑后保存不使用该身份缓存，防止复用旧编辑结果。不可变对象的已核实包位置仅缓存最近一次目录；从旧主文件读取的索引需要核实包成员及内容摘要后才能复用，不能把合法包名当成成员存在的证明。

先准备新增载荷并合并成不可变包，各包写入同目录临时文件、刷盘并替换目标文件。依赖包全部准备后，主文件流式写入临时文件、刷盘并原子替换，不为补充引用构造整份主文件的可变 JSON 树。主文件替换失败时原主文件仍可读取；此前写入但未被引用的块不改变原恢复结果。没有对过往分块进行就地修改或在保存中删除旧块，因此读取者不会因正在保存新一代检查点而失去旧引用。

## 读取与兼容

当前分块主文件包含 `CheckpointStorage: 2`，磁盘模型版本写为 `chunks2:<原模型版本>`；包内容为 `{ "$chunks": { "<载荷摘要>": <原始JSON>, ... } }`。新读取器同时支持 v1 的 `CheckpointStorage: 1` / `chunks1:` 独立块，校验存储版本并恢复原模型版本，再交给 Core 检查素材及配置兼容性。v1 不接受包引用；旧程序会拒绝 v2，避免把引用误当作空事件。

没有存储标记的旧全量文件继续按旧格式读取，但不能包含分块引用。分块名称仅允许 64 位大写十六进制摘要；读取时先校验整包 SHA256，再校验指定成员的 SHA256、完成标志、目录及文件重解析点；同次加载缓存已验证的包，结束即释放，拒绝损坏、缺失或越界引用，不把不完整记录作为正常结果恢复。

队列扫描、历史按需加载与一次性恢复均通过同一读取入口。历史导出得到的仍是完整 `ProcessingState`，不向算法暴露文件引用。

## 清理

正常完成时先等待进度写入排空，再移除主文件及本任务摘要命名的块文件。一次性恢复先完整读入各任务，再消费主文件与块文件。只清理本任务块目录里的已知文件，不递归跟随目录联接；块清理失败会记录警告，不让已经读入的恢复任务因此丢失。

更多素材的磁盘中断恢复及多轮性能对照仍需继续验证。当前测试覆盖旧格式、完整状态往返、完成块复用、活动事件更新、编辑后保存、损坏和路径引用拒绝、提交失败保留旧状态、摘要按需加载与真实解码器恢复，以及时间码追加、变帧率、旧项修正后的块失效和恢复。

## 2026-10-28 长视频磁盘恢复验证

通过 ApplicationBenchmark 的分块模式，使用 `event200_tsukasa_01` 输入三件套（2768×1280、60 fps、声明 19191 帧），固定 4 个匹配线程、8 帧预读及 WPF 离屏预览。连续运行与 35% 取消后从磁盘恢复均以 Completed 结束；取消检查点为第 6752 帧，最终为第 18811 帧（目标已全部完成）。取消时展开后的磁盘检查点与公开完整快照逐字节序列化比对通过，再由新处理器恢复。

最终完整状态 694910 字节、ASS 52154 字节均逐字节一致，状态 SHA256 为 `3EFF26D272EF864B019E22DCB3E4A56DF7708F40964C15BDCEB96B43E62037A1`，ASS SHA256 为 `6BB223DCE391EAC853F62D175B925D730E561D6C89C64616548B53BCBB4AAC6F`。本地输入摘要和报告保留在 `.codex-build/recognition-plan/chunked-long/verification.json`。

本轮只证明该素材、配置及取消边界的恢复一致性；单轮耗时不用于提速结论。仍需扩展其他素材、取消边界及多轮性能比较，也未覆盖真实窗口交互。

### 时间码块边界取消

同日以同一素材、4 线程、8 帧预读和分块保存模式重新运行连续基准，并分别在 4095、4096、4097 帧精确取消。三次磁盘恢复均从请求帧开始，最终均为 Completed；最终完整状态和 ASS 的文件长度、SHA256 及额外逐字节对照全部一致，摘要与上节相同。该组覆盖首个 4096 项时间码块形成前后的处理帧边界。

使用 [VerifyChunkedResume.ps1](../Tools/ApplicationBenchmark/VerifyChunkedResume.ps1) 顺序运行，运行前后输入三件套及工具目录 DLL/JSON 摘要一致。报告与身份清单保留在 `.codex-build/recognition-plan/chunked-boundaries/verification.json` 和 `identity.json`。该组不构成多素材、多轮性能结论；还需扩展其他素材、事件状态边界及长公共前缀场景。

## 按规模选择全量与分块

队列的增量接口现采用自适应存储策略：紧凑完整 JSON 不超过 1 MiB 时原子写入单个文件；超过后沿用上述不可变分块协议。完整文件保存原模型版本和普通时间码数组，既有读取器可以直接读取。处理期冻结的时间码块直接顺序写成数组，不先复制为完整列表。

选择过程先以帧记录和时间码的保守最小编码体积排除明显超限状态；其余状态通过有界候选缓冲实际序列化，超过上限即放弃候选，进入分块路径，不写出半个主文件。1 MiB 是当前策略的工程阈值，不代表所有磁盘和任务的最优交点。没有改变原子替换、刷盘、摘要验证或失败保留旧版本的规则。

同一任务允许全量→分块→全量切换；切回全量时不立即删除旧块，避免破坏尚在读取上一代主文件的读取器，任务删除时统一清理。协议单元测试通过显式强制分块入口继续覆盖损坏及拒绝路径，产品仍按规模选择。新增回归覆盖上限前一字节、精确上限、上限后一字节，实际冻结时间码展开、两种大状态选择路径、双向切换和两种替换失败；真实解码器恢复分别验证全量与强制分块。

## v2 包协议额外验证

新增回归覆盖 v1 读取与不重写复用、多个事件和时间码共包、包缺失后的重建、外层摘要正确但内层载荷被改动、成员缺失、路径与版本拒绝，以及冷/热缓存下错误旧包绑定不得污染新保存。还覆盖包发布失败、主文件替换失败和流式写入中途异常：旧主文件保持不变，临时文件清理，孤立包不影响旧一代恢复。大活动轨迹保持内联，并验证超过 1 MiB 的主文件仍完整往返；超大完成事件以未包装内容文件保存，避免大对象再次套包。


### 默认策略取消点格式校验入口

`VerifyChunkedResume.ps1 -RequirePackedCancellation` 要求每个取消点留存的 `canceled-manifest.json` 使用 `CheckpointStorage: 2` 和 `chunks2:` 版本前缀。该参数仅检查默认策略的实际选择，不强制切换格式；需要强制模式时另传 `-ForcePacks`。工具先从原检查点加载并比较取消时完整状态，再交给新处理器恢复，最终与同轮新生成的连续识别状态及 ASS 比较。原始清单副本用于格式证据，恢复读取的仍是原路径和原分块目录。运行前后还比较输入、模板及工具目录 DLL/JSON 的 SHA256。


## 默认 v2 长素材恢复（2026-10-28）

横幅完成快照复用修正后，以 `wl_3rd_group4_05.mp4` 三件套（3008×1880、60 fps、声明 81072 帧）运行全新连续识别及第 60000 帧精确取消恢复，固定 4 匹配线程、8 帧预读、WPF 离屏预览；未启用 `ForcePacks`，启用 `RequirePackedCancellation`。取消点留存清单为 `CheckpointStorage: 2`、`Version: chunks2:2.0`，展开状态 2176483 字节。磁盘恢复状态与取消时公开完整快照序列化一致，新处理器从 60000 帧恢复，两次均以 Completed 结束，共识别 196 个对话、4 个横幅。

最终完整状态 2913291 字节，SHA256 `954DBB584C53BFAB13AE2C8C0739A3CBBB933176999A1F65B2AB8FA597D8CF64`；ASS 217531 字节，SHA256 `DD2E85662C016C535DF5AE4EAC506E6F41EB0483631675E2629A9F68E9296FB8`。脚本长度与摘要检查以及额外逐字节对照均一致，运行前后输入、模板和工具 DLL/JSON 身份一致。证据保留于 `.codex-build/recognition-plan/long-default-v2-resume/` 的 `verification.json`、`byte-verification.json`、`identity.json` 和取消点原始清单。

连续运行 437.30 秒，取消并恢复总计 430.83 秒；两种生命周期不同且各仅一次，这些数据只记录验证成本，不支持提速结论。本组补足默认策略实际 v2 的长素材恢复证据，尚不覆盖全部取消边界、真实窗口交互或真实瞬时同前缀切换正例。

反例验证使用小素材 `1963_areatalk_ev_street_16_003` 在第 1029 帧取消：实际为全量清单，开启 `RequirePackedCancellation` 后脚本按预期报错且未生成成功验证报告，避免把增量接口启用误当作实际 v2 覆盖。证据位于 `.codex-build/recognition-plan/require-packed-cancel-negative/`。
