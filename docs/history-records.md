# 历史记录加载与界面

点击字幕页的历史记录入口后，列表按未完成任务、已完成历史分组。每条记录横向铺满列表，显示视频文件名、时间和状态；右侧“加载”按钮加载该条处理结果，点击卡片正文不会加载。清除历史仅影响已完成记录。

打开列表时后台扫描 JSON 摘要，跳过逐帧位置、时间码及匹配器状态的对象构造。点击加载后才读取该条完整状态，并在后台初始化视频处理器和恢复状态；结果控件通过 DispatcherBatchQueue 分批更新。窗口关闭会等待正在加载的历史释放处理器。

## 未完成任务的一次性恢复

首次进入字幕页扫描上次未完成任务时，先将检查点读取到内存并消费磁盘记录，再提示是否恢复。选择“放弃恢复”或关闭提示后，下次启动不再提供这些任务。素材缺失的旧记录也会消费，避免以后反复出现。

队列恢复使用队列检查点；同一任务的旧进度副本同时清除。兼容旧版只返回最近一条进度的行为，但消费所有旧版未完成进度文件，防止更旧的记录在下次启动重新出现。已完成历史记录不受影响。

恢复加入队列的任务本次会话内正常识别、预览及导出，但不再写入恢复检查点，关闭或移除后无法再次恢复。恢复任务处理完成时仍可写入已完成历史。新建任务继续正常保存进度，拥有自己的一次恢复机会。

- 294 项测试通过，包含完整状态按需加载、摘要跳过匹配器载荷、进度去重、坏文件跳过和不删除原文件的检查；WPF GUI 构建通过。
- 独立 WPF 渲染探针检查深浅主题、480／720 DIP 内容宽度：三条卡片全部铺满，正文点击不选择记录，右侧按钮选择对应记录。截图与日志保存在被 Git 忽略的 `artifacts/history-smoke/`。
- 本机原有 6 个历史文件总计约 14.8 MB。首次运行预热后，连续三轮完整历史读取为 146.6／122.6／122.8 ms，每轮线程分配约 78.6 MB；新摘要目录包含 6 条历史和 2 条未完成记录，为 62.2／59.8／56.5 ms，每轮线程分配 21,912 字节。两者扫描范围不同，且为同进程热缓存诊断，仅说明避免完整对象分配的收益，不能作为任意素材或端到端加载性能保证。
