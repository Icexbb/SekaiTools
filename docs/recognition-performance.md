# 识别性能与诊断

本文保留识别优化的运行约束、最终取舍与复测入口；不将历史实验的单次输出或未完成候选包当作当前发布状态。识别算法及未完成校准见 [字幕识别规则](recognition.md)。

## 缓存与预读

逐帧上下文共享灰度图，按 ROI 延迟生成缩放层；匹配模板及 Gray/Alpha 多尺度层按任务复用。结果缓存只复用同一帧、同一图像、ROI、模板、匹配算法及接受阈值的结果，不跨任务共享，也不做跨帧逐像素比较和整图克隆缓存。相关实现见 [FrameMatchContext](../SekaiToolsCore/Match/TemplateMatcher/FrameMatchContext.cs) 和 [TemplateMatchCachePool](../SekaiToolsCore/Match/TemplateMatcher/TemplateMatchCachePool.cs)。

开启详细匹配计时后，任务报告按模板用途和搜索、逐字出现、稳定跟踪、失配恢复、前瞻五类调用状态统计请求、缓存命中、相关计算次数和请求耗时，包含前瞻的独立正文复核。状态表示请求进入时的阶段，内部尺度复核仍归调用方；用于区分持续跟踪和失败搜索的成本，不作为置信度。分组与用途汇总不能重复相加，关闭详细计时不采集。字段及使用方式见 RecognitionBenchmark 说明。

性能模式由 [RecognitionPerformanceOptions](../SekaiToolsCore/Process/Config/RecognitionPerformanceOptions.cs) 定义：

| 模式 | 新增缓存预算上限 | 帧池上限 |
| --- | ---: | ---: |
| 节省内存 | 128 MiB | 4 帧 |
| 自动（默认） | 512 MiB | 16 帧 |
| 高性能 | 用户设置 128–4096 MiB，默认 2048 MiB | 32 帧 |

启动时再按可用物理内存的四分之一限制预算，节省内存预留 64 MiB，其他模式预留 96 MiB 给匹配及预生成缓冲。BGR 帧按每像素 3 字节估算，开启后台灰度后按 4 字节；不足两帧则回退串行读取。用户设置的预读上限只能进一步限制容量，预算不是整个进程的内存上限，也不会预先全部分配。

解码线程独占捕获器，顺序交付帧号、实际时间码及帧对象，池满则等待、不丢帧。检查点记录已消费位置，不跳过预读但未识别的帧。停止、正常结束及异常均先等待解码任务，再释放帧池和捕获器。

## 模板、预览与资源生命周期

每个处理器的进度写入最多保留一份正在写入的快照和一份最新待写快照；磁盘较慢时替换尚未开始的旧快照，写入失败会记录错误并继续处理最新快照。停止和退出等待最终队列排空。Windows 队列对不超过 1 MiB 的紧凑状态保存完整文件，较大状态将已完成事件按摘要分块保存，只更新新增完成块与主文件；旧全量进度仍可读取，协议及清理规则见[队列检查点分块存储](checkpoint-storage.md)。

处理期间的检查点复用已完成对话与角标的逐帧 DTO，仅重新构造未完成事件的轨迹；普通捕获、历史与导出仍重新读取当前编辑结果，不复用处理期缓存。恢复状态和释放匹配器清空缓存。快照请求同时受 30 秒墙钟上限约束，在后续可处理帧到达时触发，内容起点搜索也参与此规则；这不是慢磁盘或阻塞解码下的持久化完成时间保证。增量持久化实现的时间码按 4096 项冻结和保存，只复制尾块；公开捕获及旧持久化实现仍使用完整列表。正常完成先等待在途写入，再删除检查点，避免旧写入重建已经清理的文件。

识别缓存紧凑的匹配模板，不因匹配而保留大幅原彩色文字图；裁剪结果拥有独立存储，Skia 到 OpenCV 避免中间托管大数组。公开模板缓存与调用方拥有的临时图像区分释放责任。

自动／高性能模式预生成后续各最多四个对话、横幅和角标模板及缩放层，缓存上限 16 MiB，预算另预留临时画布空间；节省内存模式不启用。重置先取消并等待预生成任务，再释放缓存。

预览保持比例缩至 960×540 内，不放大小视频；关闭预览时跳过缩放和排队。结果 UI 使用有界分批队列并合并时间轴重绘。识别仍使用完整帧，预览尺寸不是匹配分辨率。后台灰度及内容位置探测默认关闭，详细匹配计时也默认关闭。

重置等待工作线程、结束回调及后台进度保存，释放处理器后再清空预览、列表和时间线。用户明确重置时可执行后台完整回收，不在逐帧循环中触发，也不强制裁剪工作集。原生运行库和 WPF 热身会提高常驻占用，不能用冷启动内存作为释放目标；应观察热身后的连续任务、弱引用和解码器句柄。

正式比较固定输入三件套、模板、运行库、配置及硬件；至少三轮、独立进程交替执行，期间不并行构建或运行其他性能作业。诊断时开启细分计时，测量最终速度时关闭采样开销。

逐轮核对完整状态、坐标、时间码、尺度、终止原因及实际 ASS 字节。实验身份只能按事先明确的规则验证，不能任意删除差异字段。取消恢复要用磁盘检查点及新处理器与连续识别比较，不能仅测普通完成路径。

区分处理阶段耗时、整进程墙钟时间和 WPF 渲染；预读使阶段重叠，耗时不能直接相加。峰值工作集需说明是否包含预热和前轮。单轮用于筛选，前缀像素检查只能发现早期差异，不能证明完整视频等价。

## 历史实验的最终取舍

下列结论来自 2026-10 的本机样本，保留作复测依据，不是本次文档整理重新测得的结果。

| 方向 | 证据与取舍 |
| --- | --- |
| 紧凑模板缓存 | 80 个文本的局部测试，私有内存增量从约 629 MiB 降至 6 MiB；不代表整任务按同一比例减少。 |
| 有界预读 | 1080p/600 帧空剧本合成样例吞吐改善，但增加帧池内存；不能外推到完整剧情。 |
| 后台灰度 | 合成样例未显示稳定提速，峰值内存增加，保持默认关闭。 |
| 低匹配线程／较小帧池 | 五组素材、三轮交替的完整状态与 ASS 一致，4 线程／8 帧组合在该机降低耗时与内存；设置仍默认自动，不推导通用最优值。 |
| 实际时间预览节流 | 两份素材的预览转换和渲染累计成本显著下降，长片总耗时降低，短片有回退；不宣称所有素材更快。 |
| MSMF 替换 FFmpeg | 八份前缀检查存在打不开、像素或时间码差异，未接受为默认后端。 |
| D3D11 硬件解码 | 五组完整识别中三组状态及 ASS 改变，且单轮均更慢；撤回产品分支，只保留隔离实验。 |
| 浮点模板／掩码缓存 | 输出一致但完整任务收益混合、内存增加，未进入产品；复现补丁留在工具目录。 |
| AVX2、IPP 及低线程组合 | 必须核对实际原生构建；不能将已有算子分派或组合收益全部归因于 OpenCV 5 新特性。 |
| BGRA 输出 | 前缀像素检查通过，但代表样例更慢且增加帧存储，未采用。 |

周期彩色是默认关闭的独立实验：识别帧输出灰度，按预览周期保留彩色；[产品工厂](../SekaiToolsInfrastructure/Video/PeriodicColorCaptureFactory.cs) 校验运行库及插件指纹，并把实际身份写入检查点，禁止不同身份混用。

完整模块扩展候选在当时的五组、三轮共十五对中通过状态与 ASS 对照，整进程配对耗时降幅中位数约 1.00%–5.79%，峰值工作集下降约 68–97 MiB，但有一对耗时回退；最后两对为中断后补测，不是连续测量。有限模块旧候选不等同完整 SDK，模块／导出数一致也不能证明完整 ABI。窗口行为探针与可见界面人工验收分开，历史本地候选目录、版本及哈希不得当作当前正式发布依据。

## 文件选择延迟排查

浏览与拖放最终都进入 [SubtitleTaskSetup](../SekaiToolsGUI/View/Subtitle/Components/SubtitleTaskSetup.xaml.cs) 的配套文件选择逻辑；浏览额外调用 Windows 文件对话框。配套查询在后台执行，关闭自动匹配则跳过，连续选择或关闭窗口会使旧结果失效。

日志区分对话框开始、`FileOk`、返回及配套查询。对话框总耗时包含用户操作，`FileOk` 也不是鼠标点击时刻，它发生在路径获取和校验之后。`FileOk` 到返回很长时先查关闭阶段；确认后到 `FileOk` 很长时查系统路径验证，不能只凭总时间归因于缩略图、杀毒软件或最近文档登记。

周期彩色资格检查在启动时触发并在进程内缓存，普通非实验任务跳过实验工厂；实际使用和恢复实验状态仍校验身份。2026-10-12 的本机配套匹配测试未复现长阻塞，不能称用户问题已彻底解决。若仍可复现，应在该设备采样实际对话框调用栈和分段日志；工具入口见 [PeriodicColorSettingsProbe](../Tools/PeriodicColorSettingsProbe/README.md)。

## 自适应检查点验证（27885d6，合包前）

小检查点已改为不超过 1 MiB 时写紧凑全量 JSON，序列化元数据复用，冻结时间码惰性展开；明显超限的帧/时间码体积下界可直接选择分块。大小边界、双向格式切换、提交失败和真实解码器两格式恢复纳入回归，完整测试 470 项通过。真实短素材在 1029、2048、3000 帧取消后的状态及 ASS 与连续运行一致。

新增 CheckpointBenchmark 区分缩进和分块收益，使用两个合成规模、四模式、四独立进程轮换，每种模式连续五次追加活动轨迹及时间码，共 160 次保存后加载比较全部一致。下表是各统计项分别计算的中位数，不能相加推导另一项。大状态包含 64 个完成事件、256000 条完成轨迹，初始 300000 项时间码；工具先运行小规模再运行大规模，不是纯冷启动大状态测试。

| 模式 | 小状态五次合计 | 大状态初次 | 大状态后四次追加合计 | 大状态五次合计 |
| --- | ---: | ---: | ---: | ---: |
| 旧缩进全量 | 46.46 ms | 109.03 ms | 321.00 ms | 430.03 ms |
| 紧凑全量 | 25.09 ms | 27.62 ms | 121.09 ms | 147.54 ms |

小状态最终紧凑文件约 0.65 MiB，自适应不创建分块。大状态分块后的追加成本较紧凑全量下降，但首次创建多个文件很贵，五次合计仍慢于紧凑全量。因此当前阈值只改善已测小检查点并保留分块能力，不证明全局最优；后续仍需结合保存次数、首次分块成本及中间规模选择策略。该基准仅测后端保存，不包含状态构造及完整识别，不能换算整段提速。源数据及程序集身份记录于 `.codex-build/recognition-plan/storage-policy-cached/`，载荷验证后已由产品删除入口清理。

当前同构建真实短素材另行完成三轮 legacy/自适应交替：完整状态与 ASS 一致，耗时中位数 8.020/7.981 秒，配对降幅中位数 0.16%，保存累计耗时中位数 45.96/48.46 ms（均四次调用）。差异很小，未证明稳定总耗时收益。报告保留在 `.codex-build/recognition-plan/adaptive-small-comparison/`；仍需长素材复测，不能将此前强制分块的结果直接当成这次自适应策略表现。

## v2 小块合包与流式提交验证

当前 v2 将约 1 MiB 以内的新载荷合为不可变包，单个超目标载荷保持独立内容文件。保留旧 v1 读取及引用复用、两层摘要校验和包先刷盘、主文件最后提交的顺序；旧索引需验证成员，活动轨迹不构造第二份可变 JSON 树。同一保存批次复用包存在检查及已准备的引用，跨保存重新检查缺失。新增测试覆盖协议迁移、损坏与错绑索引、发布及流式异常、超大单载荷和大活动轨迹；完整测试 480 项通过。

同一最终构建四模式、四独立进程轮换，两个规模各连续五次追加轨迹及时间码，160 次保存后加载均与完整状态一致。各项独立计算中位数，不能相加推导总数。

| 模式 | 小状态五次合计 | 大状态初次 | 大状态后四次追加合计 | 大状态五次合计 |
| --- | ---: | ---: | ---: | ---: |
| 旧缩进全量 | 48.06 ms | 102.71 ms | 349.33 ms | 452.04 ms |
| 紧凑全量 | 27.26 ms | 32.31 ms | 116.57 ms | 148.71 ms |
| 自适应（大状态使用 v2） | 34.06 ms | 79.32 ms | 36.90 ms | 119.48 ms |
| 强制 v2 分块 | 43.10 ms | 91.23 ms | 38.50 ms | 129.73 ms |

大样例首次只有 12 个载荷文件，五次后为 16 个（含此前尾块）；合包前对应为 138/142 个。此前 27885d6 独立测量的自适应首次成本为 261.41 ms，当前为 79.32 ms；这是阶段性参考，不是两个版本交替配对的统计。当前同构建对照显示分块首次仍比紧凑全量更贵，但该大样例五次总成本已较低；小状态仍走全量，不能将此推导为所有大小、保存次数或整段视频的提速。报告、程序集身份及全部逐轮数据保留于 `.codex-build/recognition-plan/storage-policy-pack-large-safe/`，验证后的载荷已清理。

另以实际短视频强制使用 v2，而非依赖默认自适应选择，在 1029、2048、3000 帧精确取消并核实磁盘存储版本为 2；新处理器恢复后，完整状态及 ASS 均与连续运行逐字节一致。报告位于 `.codex-build/recognition-plan/packed-v2-real-resume/`。强制模式仅是协议验证入口，不进入普通策略性能对照；整段长素材及默认策略多轮测量仍需继续。

## 当前默认策略的长素材整链三轮复测

使用 `wl_3rd_group4_05`（3008×1880、60 fps、81072 帧）、同一冻结构建、4 匹配线程和8帧预读，启用 WPF 离屏预览、关闭细分匹配计时，以 legacy 为参考、当前自适应队列为候选。每轮候选必须实际出现 v2；禁止强制分块。六次均为 Completed，完整状态及 ASS 的实际文件摘要通过检查，结束后另行逐字节比较全部一致；输入、模板和 DLL/JSON 身份在整组结束再次核对通过。

**第三轮为中断后补测，不能称连续三轮。** 原控制会话及第三轮参考进程在未形成报告时已结束，原因没有足够日志证明。核实实际进程不存在后保留未完成目录，重新核对同一身份，复用前两轮已完成且文件校验通过的报告，只补第三轮参考和候选。`interruption.json` 保留了该事实；第三轮不能因为结果不利而删除。

总耗时中位数为参考 392.784 s、候选 393.043 s；配对耗时增加中位数约 0.196%。两个中位数之比不是配对中位数。当前证据没有证明端到端提速，并观察到单次较大回退；无法仅据此把回退归因于持久化或外部负载。保存阶段累计中位数 302.26/441.45 ms，候选更高；保存异步重叠，不能直接从总耗时扣除。两边文件头检查开销中位数约 4.99/5.66 ms；最后一轮的保存调用数也不同。

独立进程峰值工作集中位数约 782.44/720.45 MiB；这是本机该工具的峰值，不能推导完整 GUI 内存，也不能单独归因于某项优化。后端合成样例的收益不能代替本次真实整链结果。
