# 文件选择延迟排查（2026-10-12）

用户反馈：选择文件后，同目录同名的视频、剧本和翻译迟迟未完成匹配，且每次发生。

## 已确认的调用链与改动

- 文件浏览入口调用 Windows 文件对话框，返回后只检查同名候选文件是否存在并更新路径；这段调用链没有解码视频，也没有直接调用周期彩色资格检查。
- 旧版设置模型每次构造都会加载 OpenCV 并计算运行库/插件哈希。生产设置实例本身是单例，不能因此断言每次选文件都会重复检查。
- 资格检查现在由 `App.OnStartup` 在创建窗口前触发，进程内缓存结果；后续设置对象复用缓存，未启用周期彩色的普通任务继续跳过实验捕获工厂。实际启用实验或恢复实验断点时保留捕获工厂的安全验证。
- 配套文件查询移出界面线程；关闭自动匹配时直接返回，不再查询配套文件。连续选择用序号防止旧结果覆盖新选择，关闭窗口后的结果不再应用。
- 日志分别记录启动资格检查、文件对话框和配套文件匹配耗时。文件对话框耗时包含用户操作，不能直接当作程序阻塞时间。

## 实测

在 `E:\ProjectSekai\test` 的四组素材上，用实际 WPF 选文件控件测试。每组分别选择 `.mp4`、`.json`、`.txt`，各重复三次，共 36 次；原始运行库与合格实验运行库分别验证。

| 场景 | 20 次设置模型初始化总耗时 | 配套匹配中位数 | 最大匹配耗时 |
| --- | ---: | ---: | ---: |
| 旧版 GUI 对照（原始运行库） | 1967 ms | 0.14 ms | 1.41 ms |
| 修复版（原始运行库） | 142 ms | 0.80 ms | 10.18 ms |
| 修复版（合格实验运行库） | 151 ms | 0.78 ms | 9.83 ms |

修复版两个进程的启动检查分别约 246 ms、393 ms；各进程日志均只出现一次资格检查。异步调度增加了少量匹配总延迟，其作用是避免磁盘查询阻塞界面，并非证明本地匹配速度提升。

36 次匹配、连续选择、关闭自动匹配、不可用实验自动取消并禁用、合格实验的设置绑定与保存全部通过。272 个现有测试通过。测试不修改用户设置、进度和历史文件。

证据目录：`.codex-build/file-selection/`；`PeriodicColorSettingsProbe <新输出目录> selection <素材目录>` 可复测。

## 待实际复现确认

本机旧版对照未复现用户描述的长时间阻塞，根因尚未确认。使用新构建重启后，若仍卡顿，应查看日志中“文件对话框（含用户选择时间）”与“匹配配套文件”的时间，结合卡顿发生在对话框打开、文件确认还是返回之后，继续定位 Windows 文件对话框或磁盘访问延迟。不能把现有证据解释成卡顿已彻底解决。
