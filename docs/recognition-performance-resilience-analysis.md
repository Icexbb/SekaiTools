# 识别精度、处理速度与容错率改进分析

## 1. 分析范围

本文针对 SekaiTools 自动轴机的核心处理链路进行分析：

```text
视频解码
  -> 内容开始标记识别
  -> 对话 / 横幅 / Marker 模板匹配
  -> FrameSet 时间与位置数据
  -> ASS 字幕生成
```

主要涉及以下代码：

- `SekaiToolsCore/VideoProcessor.cs`
- `SekaiToolsCore/Match/TemplateMatcher/`
- `SekaiToolsCore/Process/FrameSet/`
- `SekaiToolsCore/Process/ProgressStore.cs`
- `SekaiToolsCore/SubtitleMaker.cs`

项目当前已具备 ROI 裁剪、二倍降采样、模板缓存、顺序状态机、异常熔断、进度保存和断点恢复等能力。当前主要瓶颈并非单纯的匹配阈值，而是缓存正确性、严格顺序匹配、重复图像预处理以及缺少真实视频识别测试集。

## 2. 总体结论

建议按照以下顺序改进：

1. 先修复缓存、输入边界和共享对象修改等正确性问题。
2. 再消除重复灰度转换、模板缩放和原生图像分配。
3. 引入粗到细定位、状态感知采样和有限事件前瞻。
4. 建立真实标注视频集，根据量化结果校准阈值与算法。

直接调整 `0.75`、`0.80` 等阈值只能局部缓解漏检，并可能显著增加误检，不能替代上述结构性改进。

## 3. 关键问题及优先级

| 优先级 | 问题 | 主要影响 |
| --- | --- | --- |
| P0 | 模板缓存键不包含模板、ROI 和处理器实例 | 复用错误分数，产生误检或漏检，并发任务互相污染 |
| P0 | 匹配器严格停留在当前剧本事件 | 一条缺失内容可能阻塞后续全部事件 |
| P0 | ROI 和短文本缺少完整边界检查 | 重复异常、跳帧，严重时触发异常熔断 |
| P1 | 降采样搜索后没有原分辨率局部精修 | 小文字分数下降，位置存在量化误差 |
| P1 | 每次匹配重复生成灰度图和缩放模板 | CPU、内存分配和原生对象管理开销较大 |
| P1 | 使用固定 FPS 推导字幕时间 | 可变帧率视频可能逐渐产生时间偏移 |
| P1 | 进度恢复只根据文件路径识别输入 | 文件被替换后可能恢复不兼容状态 |
| P2 | 缺少核心识别与性能测试 | 无法量化优化收益，也难以防止回归 |

## 4. 识别精度改进方案

### 4.1 修复模板匹配缓存

`TemplateMatchCachePool` 当前主要按匹配用途和帧号缓存。帧号相同时会直接返回已有结果，但缓存键没有包含：

- 模板内容或模板 ID；
- ROI 坐标及尺寸；
- `TemplateMatchingType`；
- 当前 `VideoProcessor` 实例。

状态机可能在同一帧内结束上一条事件并立即尝试下一条事件。此时即使模板已经变化，也可能复用上一模板的结果。缓存又是静态全局对象，多任务并发处理时还可能互相污染。

建议：

- 将缓存改成每个 `VideoProcessor` 独立的 `FrameMatchContext`。
- 缓存键至少包含 `(frameIndex, roi, templateId, matchingType)`。
- 模板对象使用不可变 ID，不以调用方枚举值代替模板身份。
- 优先缓存每帧灰度图和图像金字塔，而不是缓存键不完整的最终匹配结果。
- 评估删除跨帧逐像素 `Compare`：它需要扫描 ROI，随后大多数情况下仍需模板匹配和图像克隆，可能成为负优化。

### 4.2 使用粗到细的两级匹配

当前算法把输入和模板缩小二倍进行全局搜索，再将低分辨率坐标直接换算回原图，没有原分辨率精修。

建议改为：

1. 在二分之一分辨率上全局搜索候选峰值。
2. 在原图对应位置周围建立小范围 ROI。
3. 使用原分辨率模板重新匹配。
4. 用精修后的相关系数和坐标作为最终结果。

该方案能保留降采样搜索的大部分速度优势，同时提高小字号、压缩画面及位置跟踪的精度。

### 4.3 增加有限多尺度搜索

模板尺寸主要根据视频分辨率推导，无法完全覆盖录屏裁边、播放器缩放、编码重采样和非标准 UI 缩放。

建议：

- 初始化阶段尝试 `0.94、0.97、1.00、1.03、1.06` 等有限尺度。
- 确定当前视频的最佳尺度后，后续锁定该尺度或只搜索相邻尺度。
- 分别记录 Dialog、Banner、Marker 的最佳尺度，不强制共用。
- 把尺度写入处理状态，确保断点恢复结果一致。

### 4.4 从单阈值改为置信度组合

仅使用 `MaxVal > threshold` 无法区分清晰峰值与多个相似候选。

建议综合：

- 第一峰相关系数；
- 第一峰与第二峰的差值；
- 峰值邻域锐度；
- 连续帧分数稳定性；
- 与上一帧位置的移动距离；
- 与上一剧本事件的时间距离。

同时使用进入阈值和退出阈值形成迟滞，避免相关系数在阈值附近波动导致事件反复进入和退出。

当前代码多处排除 `MaxVal == 1`。完全匹配本身可能是合法结果，不应一律拒绝。更合理的做法是检查：

- 分数是否为有限值；
- 模板和 ROI 是否具有足够方差；
- 有效 Alpha 像素数量是否达到下限。

### 4.5 按事件类型选择图像特征

纯灰度相关匹配容易受亮度、透明动画和视频压缩影响，可按类型分别处理：

- 对话文字：局部亮度归一化，并结合边缘或距离变换。
- 横幅：同时保留背景亮度结构和文字边缘信息。
- Marker：联合整体宽度、固定左上区域和末尾字符分数。
- 内容开始标记：要求连续 2～3 帧命中，降低偶发 UI 图形误触发概率。

现有系统已知目标文字，模板匹配通常比通用 OCR 更快、更稳定。OCR 更适合作为低置信度目标的兜底，而非直接替换主流程。

## 5. 处理速度改进方案

### 5.1 每帧只执行一次图像预处理

当前不同模板匹配调用可能分别执行 BGR 到灰度转换。建议在视频主循环中创建共享帧上下文：

```text
FrameMatchContext
  |- 原始 BGR 帧
  |- 灰度帧
  |- 1/2 灰度帧
  |- 可选边缘帧
  |- Dialog ROI 视图
  |- Banner ROI 视图
  `- Marker ROI 视图
```

Dialog、Banner 和 Marker 只引用共享图像或 ROI 视图，不再各自转换和复制数据。

### 5.2 缓存真正用于匹配的模板

`TemplateManager` 缓存了 BGRA `Mat`，但 Dialog 和 Banner 仍会频繁构造 `GaMat`，重复执行：

- 灰度转换；
- Alpha 通道提取；
- 五倍缩小；
- 搜索阶段的再次缩小。

建议按 `(usage, text, scale)` 缓存不可变模板资源：

- 原尺寸 Gray/Alpha；
- 二分之一尺寸 Gray/Alpha；
- 边缘或其他特征图；
- 模板唯一 ID。

Marker 已进行部分缓存，但当前实现会原地缩放 `TemplateManager` 返回的共享 `Mat`。应先克隆再缩放，避免修改模板管理器中的共享数据。

### 5.3 状态感知的时间采样

统一每隔 N 帧识别会损失字幕边界精度。建议根据状态动态采样：

- 尚未发现目标：每 2～4 帧搜索一次。
- 发现疑似目标：回看最近区间，逐帧或二分精修开始边界。
- 对话正在显示：抖动对话逐帧跟踪，静态对话可降低频率。
- 横幅稳定显示：降低匹配频率，中间帧直接延续状态。
- 疑似消失：恢复逐帧匹配以确定结束边界。

这样可以减少长空白区间和稳定显示区间的工作量，同时保持起止帧精度。

### 5.4 流水线并行

在确认 Emgu CV 对象的线程归属和生命周期后，可将处理拆成有界流水线：

1. 解码线程读取视频帧和 PTS。
2. 预处理线程生成灰度图和图像金字塔。
3. 匹配线程执行状态机。
4. UI 预览线程只消费最新帧。

队列必须有界，并明确每个 `Mat` 的所有权和释放责任，避免为了并行导致原生内存增长。

## 6. 容错率改进方案

### 6.1 引入有限事件前瞻

Dialog、Banner、Marker 当前主要搜索第一个未完成事件。若剧本和视频缺少一条内容，匹配器可能一直停留在错误目标。

建议：

- 同时评估当前目标和后续 3～5 个同类型目标。
- 综合视觉置信度、事件顺序和时间距离选择最佳目标。
- 高置信度命中后，将被跨过的事件标记为“疑似缺失”，而不是静默完成。
- 提供严格模式，要求完全按照剧本顺序识别。
- 给单目标设置最大搜索帧数，但不要因此终止整个任务。

### 6.2 改进降级阈值状态机

当前降级阈值只在触发后执行一次低阈值重试，失败后立即恢复正常阈值。

建议：

- 进入降级模式后维持固定帧数。
- 降级期间要求更强的时间连续性或多帧确认，以抵消误检风险。
- 连续高置信度成功后恢复正常阈值。
- 设置最低阈值时按事件类型分别配置，避免全局使用同一绝对下限。

### 6.3 统一输入和 ROI 防御

当前存在以下风险：

- Dialog 直接读取正文前一个、前两个或前三个字符。
- Marker 直接读取正文最后一个字符。
- 部分 Banner ROI 没有统一限制在画面范围内。
- 当前矩形限制逻辑调整位置，但 ROI 大于画面时不会缩小尺寸。

建议提供统一的 `TryCreateRoi`：

- 使用画面边界与目标矩形求交集。
- 验证 ROI 尺寸不小于模板尺寸。
- 对空文本、过短文本、缺失字形返回结构化错误。
- 单个目标无效时隔离该目标，继续处理后续事件。
- 异常回调携带 matcher、事件索引、帧号和输入文本等上下文。

### 6.4 区分正常 EOF 和读帧失败

当前一次 `VideoCapture.Read` 失败就会终止为 `ReadFailed`。建议区分：

- 正常到达视频结尾；
- 临时解码失败；
- 捕获器失效；
- 所有目标提前完成；
- 视频结束但存在未识别事件。

临时失败可重试 2～3 次，或者尝试重新定位到下一帧。最终结果应允许“部分完成并导出”，同时向用户列出未识别事件。

### 6.5 支持可变帧率时间戳

当前时间主要由帧索引和固定 FPS 推导。对于 VFR 视频，应优先使用解码器提供的每帧 PTS：

- FrameSet 保存时间戳，而不是只保存帧号。
- 帧号保留用于调试和定位。
- 无法获得可靠 PTS 时再回退到固定 FPS。

### 6.6 加强进度恢复校验

当前进度键主要基于视频、剧本和翻译文件的路径。相同路径下文件被替换后，可能恢复到不兼容状态。

建议在 `ProcessingState` 中加入：

- 文件大小、修改时间和轻量内容指纹；
- 视频分辨率、FPS、帧数；
- 剧本事件签名；
- 匹配阈值配置哈希；
- 模板资源版本；
- 状态结构版本。

恢复前验证以上字段。无法兼容时应拒绝自动恢复，或只加载已经完成的 FrameSet 供人工确认。

## 7. 测试与量化体系

当前解决方案和核心项目可以正常构建，现有 14 个测试全部通过。但现有测试没有覆盖 `TemplateMatcher`、匹配状态机或 `VideoProcessor`，因此无法评价识别精度和处理速度。

### 7.1 建议测试数据集

建立一套可重复运行的小型标注视频集，至少覆盖：

- 720p、1080p、1440p；
- 30 FPS、60 FPS 和 VFR；
- 高低码率、模糊和明显压缩噪声；
- 标准比例、黑边、裁边和非标准缩放；
- 抖动对话、短台词、单字符台词；
- 连续相似角色名或相似文本；
- 视频从中间开始、剧本缺句和录屏提前结束；
- Dialog、Banner、Marker 相邻或同时出现。

### 7.2 建议指标

| 目标 | 指标 |
| --- | --- |
| 事件识别 | Precision、Recall、F1 |
| 时间轴 | 开始/结束边界 MAE 与 P95，分别按帧和毫秒统计 |
| 位置跟踪 | 坐标 RMSE 与 P95 |
| 处理速度 | 实时倍率、处理 FPS、各阶段耗时占比 |
| 资源消耗 | 峰值内存、每千帧原生对象分配次数 |
| 容错能力 | 异常视频完成率、错误后继续识别率、未识别事件数 |

### 7.3 必需的回归测试

优先补充以下自动化测试：

1. 同一帧、同一用途、不同模板不得命中旧缓存。
2. 两个处理器并发运行时缓存互不影响。
3. 空文本、单字符文本和超长文本不会抛出未处理异常。
4. ROI 超出画面时能够安全求交或返回失败。
5. 完全匹配分数为 1 时可以得到合法结果。
6. 缺失当前事件时能够匹配有限前瞻范围内的下一事件。
7. 临时读帧失败不会立即丢弃整个任务。
8. 输入文件或匹配配置变化时拒绝不兼容的进度恢复。

## 8. 推荐实施顺序

### 第一阶段：保证正确性

1. 重构模板缓存键并取消静态跨任务共享。
2. 修复空文本、短文本和 ROI 越界。
3. 禁止 Marker 原地修改共享模板。
4. 使用有限值和模板方差检查替代 `MaxVal < 1`。
5. 为以上问题添加单元测试和小型合成图像测试。

### 第二阶段：消除重复工作

1. 引入每帧共享灰度图和图像金字塔。
2. 缓存不可变的 Gray/Alpha 及多尺度模板。
3. 使用 BenchmarkDotNet 或内部计时器记录各处理阶段耗时。
4. 根据基准结果决定是否保留跨帧图像比较缓存。

### 第三阶段：改进识别算法

1. 增加低分辨率搜索和原分辨率局部精修。
2. 增加多尺度初始化和双阈值迟滞。
3. 实现状态感知采样和边界回查。
4. 实现有限事件前瞻及缺失事件诊断。

### 第四阶段：增强工程容错

1. 区分 EOF、临时读帧失败和捕获器错误。
2. 支持 VFR 时间戳。
3. 为进度状态加入输入指纹、配置哈希和版本迁移。
4. 支持部分完成结果导出和未识别事件报告。

### 第五阶段：数据驱动校准

1. 建立真实标注视频集。
2. 自动统计不同事件类型的分数分布。
3. 分辨率、压缩等级和事件类型分别校准阈值。
4. 在量化数据表明确存在收益后，再评估 OCR、OpenCL 或 GPU 加速。

## 9. 预期收益

在没有真实标注视频和性能基准前，不宜承诺具体百分比。各阶段的主要预期收益如下：

- 修复缓存：消除跨模板、跨任务结果污染，提高结果可信度。
- 有限事件前瞻：显著改善剧本缺句、录屏不完整和版本不一致场景的完成率。
- 共享帧预处理和模板缓存：降低重复颜色转换、缩放和原生内存分配。
- 粗到细匹配：提高小字号和位置跟踪精度，同时维持较高搜索速度。
- 状态感知采样：减少空白及稳定显示区间的无效计算。
- PTS 和恢复校验：降低 VFR 时间漂移与错误恢复造成的结果损坏。

最终应以第 7 节指标和固定数据集的优化前后对比作为验收依据。
