## 新特性与当前运行时能力核对

[OpenCV 5 官方变更](https://github.com/opencv/opencv/wiki/OpenCV-5)包括新的矩阵类型、图像变换、文字渲染、轮廓提取与 DNN 更新。现有标准视频路径没有几何变换、轮廓提取或 DNN 热点；不为使用新 API 引入额外处理阶段。模板匹配仍依赖灰度图与透明掩码，新增低精度类型不能直接替换其输入类型。

[HAL 文档](https://docs.opencv.org/5.0/main_modules/hal.html)说明厂商后端在构建时集成，运行时由已有算子自动分派或回退。通过新增 `Tools/OpenCvCapabilities` 查询实际 Emgu 5.0.0.6584，而非只依据版本号推断能力：

- 构建报告 `Custom HAL: NO`、线程框架 Concurrency、OpenCL YES（NVD3D11）。独立探测进程中的 `UseOptimized` 为 true，默认线程数 16。
- 独立探测进程中的 OpenCL 可用且启用，默认设备 NVIDIA GeForce RTX 5080、OpenCL 3.0 CUDA、驱动 617.14，设备与编译器可用。它不证明识别工作线程或具体算子实际使用 GPU。

原始证据位于 `.codex-build/capabilities/result/build.txt` 与 `capabilities.json`，报告同时记录工具目录 DLL 哈希。可复现命令见 `Tools/OpenCvCapabilities/README.md`。

[上游 5.0.0 模板匹配源码](https://raw.githubusercontent.com/opencv/opencv/5.0.0/modules/imgproc/src/templmatch.cpp)在非空掩码条件下先返回 `matchTemplateMask`，该函数取出 Mat 后执行计算；无掩码情况下才进入后面的 OpenCL 分支。产品当前总是传入 `template.Alpha`。据此，仅换 UMat 没有可信的热点加速依据；实际 Emgu 构建带额外提交，若探索此方向仍需核对对应实现或执行轨迹，不能将上游路径当作当前二进制 GPU 跟踪证据。

### CPU 分派热点核对与下一项后端实验

核对的是本地锁定 OpenCV `2b862f17fc625948d75840300a3837c4d0defa7a` 源码，不将通用文档当作实际执行跟踪。`templmatch.cpp` 的 TM_CCOEFF_NORMED 掩码分支调用四次 crossCorr；每次通过 hal::DFT2D 创建模板、图像正变换及逆变换。`core/src/dxt.cpp` 自带实现使用 SSE3 检查，`core/CMakeLists.txt` 的分派文件列表没有 DFT。因此，给其他算子增加 AVX2 不会直接为这份 DFT 实现增加 AVX2 内核；这只是解释有限收益的源码线索，不是 CPU 采样或每个调用的分派证明。

下一项为 OpenCV 5 的 IPP HAL／IPP 构建后端，保持模块、编译器和 CPU 分派相同，仅改变后端。需要区分以下条件：

- 锁定源码的 WITH_IPP 会自动把 ipp 加入 OpenCV_HAL；新 HAL 提供 norm、sum、minMax、meanStdDev 等路径，但该 HAL 列表没有 DFT。DFT 的 IPP 支持仍在既有 core 实现中，整体变化不能全部归因于新 HAL。
- 上游锁定 Windows x64 ICV 为 2026.0.0，下载包哈希由源码的 ippicv.cmake 固定。默认构建成功仍须检查 Custom HAL、IPP 版本与真实加载的 DLL。
- 这份 dxt.cpp 在 IPP 2022.2 及以上、IPP 启用 AVX512F 时禁用单精度 1D DFT 的 IPP 路径。但进一步核对发现：当前 matchTemplateMask 先把图像转换为 CV_32F，crossCorr 随后选择 CV_64F 作为 DFT 工作深度，故该单精度保护条件不适用于当前掩码匹配热点。默认／avx2／disabled 仍用于比较 IPP 实现差异，不能依据此保护条件预判 AVX2 更快。保持非精确 IPP 模式关闭，并实测完整状态及 ASS。

这些是实验设计依据，尚未构建或测量 IPP 候选，不能宣称后端已生效或提速。参考锁定源码的 [DFT 实现](https://github.com/opencv/opencv/blob/2b862f17fc625948d75840300a3837c4d0defa7a/modules/core/src/dxt.cpp)、[IPP HAL 接口](https://github.com/opencv/opencv/blob/2b862f17fc625948d75840300a3837c4d0defa7a/hal/ipp/include/ipp_hal_core.hpp)；[官方 oneAPI 文档](https://docs.opencv.org/5.0/tutorials/introduction/oneapi_install/oneapi_install.html)描述可选 IPP 的 DFT 支持，实际可用路径仍按当前构建和调用条件验证。
