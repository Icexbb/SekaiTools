# 地图对话筛选

数据下载页面的“地图对话”默认显示全部地点。地点、登场角色、对话 ID 范围与下方筛选方式取交集；ID 两端均包含在结果内，留空表示不限。刷新后保留地点和筛选值，原值已不存在时回退到“全部”。

“全部加入下载列表”将当前可见结果加入待下载列表，按下载 URL 跳过已有任务和本批次重复项，并显示一次加入数量与跳过数量；它不会立即下载文件。

## 筛选方式

| 方式 | 数据依据 | 说明 |
| --- | --- | --- |
| 活动解锁 | `actionSets.releaseConditionId` → `releaseConditions` → `eventStoryEpisodes.id` → `eventStories.eventId` → `events.id` | `event_story` 条件引用剧情章节；`action_set` 条件会沿前置地图对话继续解析。未知条件、缺失引用和循环依赖不强行关联活动。 |
| 活动追加（推断） | 对话 ID 顺序与已知解锁活动 | 普通对话沿用此前最新活动期数；命名可识别的特殊批次不参与这条序列。结果可能与实际追加时间不同。没有依据的条目保留在“初始／特殊批次／未归类”。 |
| 对话类型 | `actionSetType` | 普通、限定及其他实际类型，未知类型仍可选择。 |
| 更新批次 | 剧本名中的 `monthlyYYMM`、`aprilfoolYYYY`、`3rdaniv` 等周年约定及限定类型 | 每月、愚人节、周年独立归类；未知命名进入“其他更新／未归类”，未知限定对话进入“其他限定对话”。有后续活动锚点时，之前的普通对话标为“初始对话（推断）”。 |
| 归档日期（UTC+9） | `archivePublishedAt` | 显示归档日期，不代表首次追加日期。原始主数据可能含默认占位时间；未设置或超出日期范围的值进入“未设置归档日期”。 |

活动选项同时显示“第 N 期、活动名、真实 ID”。期数按有剧情且能关联活动的 `eventStories.id` 顺序编号，筛选实际使用 `events.id`，不能将期数或解锁条件编号直接当作活动 ID。

活动追加推断参考 [PRSK_Editor 的 ListManager.py](https://github.com/Sutedako/PRSK_Editor/blob/main/src/ListManager.py)，活动解锁使用主数据关联，不采用参考实现中的条件编号公式或历史硬编码特例。

## 活动元数据与降级

刷新地图对话时，`areas`、`actionSets`、`character2ds` 是必需文件；`releaseConditions`、`eventStories`、`events` 是可选活动元数据，通过当前数据源的 `{type}` 模板下载。

可选文件网络或 JSON 解析失败时，在刷新弹窗中显示“不可用（跳过）”，删除该文件的旧缓存，防止继续使用之前数据源的活动关联。活动元数据缺失或无法解析时，界面显示提示，基础筛选、类型、特殊批次和批量加入仍然可用。必需文件下载或 JSON 解析失败时不继续加载本次刷新。

## 验证

回归测试覆盖地点与角色组合、ID 边界、真实活动 ID 与期数区别、前置对话依赖及循环、按 ID 排序推断、特殊批次隔离、未知命名、缺失元数据、归档日期及可选下载失败。WPF 交互验证覆盖默认全部地点、刷新选择保留与回退、筛选值切换、非法 ID 禁止批量加入，以及重复批量加入的 URL 去重。
