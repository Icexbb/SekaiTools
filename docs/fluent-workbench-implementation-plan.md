# SekaiTools Fluent Workbench 实施方案：FlaUI 先行

编制日期：2026-11-17。依据当前 `main` 的 WPF 源码、[阶段零审计](fluent-workbench-phase0-audit.md)及项目功能文档制定。本文替代原审计中的实施阶段安排；原审计保留技术证据和风险分析。

本文定义分阶段实施范围。M0-A 的 FlaUI 工程、隔离宿主及最小运行闭环已实现，当前覆盖和运行方式见 [Windows UI 自动化测试](ui-automation.md)；其他里程碑不因此视为完成。后续按下列顺序推进。

## 1. 第一优先级：先引入 FlaUI，取得现有界面的可重复测试基线

**执行顺序：FlaUI 工程与安全测试宿主 → 现有 UI 交互与截图基线 → 设计系统 → 翻译试点 → 其余业务页 → 完整验收。**

FlaUI 不再与设计系统合并实施，也不等待页面改造后补测。最初的代码交付即包含独立测试项目、隔离环境、真实应用启动/关闭、最小 AutomationId 和失败诊断；这一闭环通过后，才开始视觉重构。

### M0-A：测试项目、隔离与最小运行闭环

1. 新增与 `SekaiTools.Tests` 平级的 `SekaiTools.UITests`，目标框架与 GUI 对齐为 `net10.0-windows10.0.19041.0`、x64；沿用现有 xUnit 2。引入 `FlaUI.Core`、`FlaUI.UIA3`，在实施时核实兼容性并锁定一致版本。
2. 加入解决方案构建，但保留业务测试与 UI 测试的独立执行入口。UI 测试使用非并行 collection，每个桌面会话只运行一个测试实例。
3. 在运行任何读写、恢复及页面初始化测试前落实数据隔离。默认设计为显式测试数据根，由组合根/配置提供接缝，生产默认路径和文件格式保持兼容；实施前列全路径调用点，不能仅改一个设置文件路径。专用 Windows 测试账户也可作为独立运行方案。
4. 覆盖 ResourceManager 数据根、下载列表缓存、设置、翻译草稿/会话、历史、队列断点、压制偏好、开发者阈值、原声缓存、下载输出、临时输出和更新目录。启动前验证解析后的路径均属于测试环境；正式目录只做未修改检查，不覆盖、消费或迁移其中内容。
5. 使用独立安装/构建目录；复用现有跳过更新机制，另外处理资源初始化和下载数据源。普通回归使用固定本地缓存或 loopback fixture 服务，所有网络地址仍由配置提供。
6. 先处理固定单实例 mutex 的限制。当前会话若有正式实例，报告冲突，不附加、关闭它或把它当作测试实例。测试会话独立运行；确需区分测试实例时，仅在显式隔离启动模式下引入实例标识。
7. 建立 `ApplicationFixture`、`TestEnvironment`、`ElementFinder`、`WaitHelper`、`ScreenshotHelper`、`TestDataManager`、`FailureDiagnostics`，职责分离。测试通过真实 exe 和 UIA3 驱动，不以反射调用 Click 处理器替代操作。
8. 只给现有外壳、代码生成的导航项、页面根和首个测试所需控件补充 AutomationId。保持现有布局，先完成启动、一次导航、截图、正常关闭。

环境预检包括交互式 Windows 桌面、会话未锁定、UIA 权限、应用与测试完整性级别、实际工作区/DPI，以及正式实例冲突。无可用桌面时明确报告“未执行”；显式 UI 验收入口应返回环境不满足，不能生成全通过结论。

关闭测试应用时走真实关闭流程，处理未保存弹窗，等待字幕保存及各队列停止。超时先保存首次失败现场，再只清理本轮创建且身份匹配的 PID/子进程，不按进程名批量结束。

**退出条件：** 连续三轮启动、导航、截图、关闭可重复完成；无自有进程残留；真实用户数据未变化；主动制造一次定位失败，能保存截图、目标 ID、页面、UIA 树、异常及清理结果。尚未改造的页面不要求已经符合新视觉标准。

### M0-B：为现有功能建立行为基线

在旧界面上完成五个入口的 Smoke、核心保存链路和固定截图场景。其余功能测试最迟必须在各页重构前补齐，先记录现状，再验证重构后行为保持。

| 测试范围 | 现有界面的最低基线 |
| --- | --- |
| 外壳 | 自动轴机、脚本翻译、数据下载、视频压制、设置与关于五个入口；导航选中态与实际页面一致；保留离开翻译页写草稿和页面缓存行为 |
| 翻译 | 载入固定 JSON 与 TXT，输入译文，保存后从磁盘重读；覆盖取消不改文件；搜索/筛选后导出顺序不变 |
| 字幕 | 添加任务、素材校验、选中与分组展示；小样本识别及 ASS 导出；专用副本验证一次性恢复 |
| 压制 | 添加任务、参数校验、详情、取消反馈；小样本真实管线独立运行，不将模拟进度当作编码成功 |
| 下载 | 固定数据源与五类列表、搜索、选择、下载队列、输出文件；失败和取消使用受控响应 |
| 设置 | 动态配置编辑器、自动保存后重启重载、还原；开发者阈值的独立保存/校验流程 |

现有缺陷单独登记，不把错误固化成期望结果。旧界面截图是行为与布局对照资料，新设计的视觉基准须在页面验收后另外确认。

当前已建立翻译保存与组合筛选、主题重载、下载主线落盘及五类空数据切换、下载受控失败/停止/重试、字幕资源与合成视频识别导出、已完成历史复用、字幕取消后重启续跑、压制真实转码及 ASS 绘图烧录基线，细节和限制见 [测试手册](ui-automation.md)。M0-B 仍有压制取消及部分设置校验场景待补齐；这些进展不代表 M1 视觉改造或真实 DPI 矩阵已完成。

## 2. 结合项目修正原始要求

| 原要求中的泛化表述 | 本项目实际行为及本次处理 |
| --- | --- |
| 保留 OCR | 常规自动轴机根据剧本和翻译，通过 OpenCV 模板匹配生成 FrameSet，再输出 ASS。保留对话、地点横幅、角标等识别与导出，不引入 OCR 引擎 |
| 统一字幕任务模式 | 常规模式与“纯视频时间轴（实验性）”分开设计、分开测试。后者检测对白区间并手工填写翻译，不能承诺已有完整常规历史/恢复能力 |
| 设置保存按钮 | 普通配置以自动保存为主；开发者阈值有独立保存与校验。测试应验证真实持久化时机，不为套模板新增全局保存按钮 |
| 所有交互都由 Command 承载 | 当前同时使用绑定、Click 处理器和服务编排；保留行为入口，仅在复用组件需要时做局部整理，不强行迁移整个 MVVM 实现 |
| 完整系统主题跟随 | 当前有明、暗及高对比路径，系统跟随实现存在注释代码；不宣称已支持。保留枚举语义，缺口单列，不在视觉改造中默默修订行为 |
| 下载页统一章节列表 | 保留主线、活动、特殊、角色、地图对话各自的数据组织和筛选语义，尤其地图对话的活动关联与缺失数据降级 |
| 新增进度/FPS/ETA | 压制已有进度、速度、已用时间、输出大小和剩余估算；复用现有模型，保留样本不足时不估算等规则 |
| 列表/网格切换、日志搜索等全部作为保留项 | 未在现有界面确认的能力属于新增交互。下载统一网格切换、日志搜索/专用复制按钮/错误高亮列为后续增强，不作为现有功能或首轮视觉重构的前置条件 |
| 全局任务管理器 | 字幕、下载、压制的队列与生命周期各自独立。可展示真实状态摘要，不为了状态栏合并调度器、统一持久化或增加业务协议 |

范围保持 WPF、WPF-UI **4.3.0**、现有 MVVM、识别与压制管线、TXT/TXT-v2/ASS 及持久化兼容性。macOS 客户端和独立 Updater 的视觉改造不纳入本轮；保留共享项目回归及发布布局启动检查。

## 3. M1：设计系统与外壳，建立可验证的公共组件

完成 M0 后才开始视觉工作。采用 Fluent 的主题、基础控件和反馈，加上适合编辑的分栏、工具栏与任务详情；保持平衡信息密度，不引入完整 IDE 式停靠框架。

- 在 `SekaiToolsGUI/Resources/Design/` 建立尺寸、字体、明暗画刷、输入/按钮、编辑器和状态模板，按实际使用拆分字典；没有使用 DataGrid 的页面不强制改成表格。
- 优先复用 WPF-UI 的主题资源和控件样式，项目资源使用一致前缀防止冲突；核对当前版本 API，不以升级依赖作为视觉改造前提。
- 间距以 4/8/12/16/24 DIP、按钮高度约 32/36 DIP、字体 Segoe UI Variable 加中文回退为起点。原文、译文、参考和长路径按内容适应，不对多行编辑框强设单行高度。
- 深色配色沿用粘贴要求作为初值，浅色独立设计；加入高对比适配。黄色参考差异、蓝色载入后修改差异和识别状态具有业务含义，主题改造必须保留区分，并配文字说明，不能只剩颜色提示。
- 外壳保留现有导航顺序，优化展开/折叠、图标与对齐。统一 PageHeader/PageToolbar，次要操作按当前窗口宽度折行或进入更多菜单。
- 分栏使用 Grid/GridSplitter 和合理最小尺寸；紧凑窗口优先折叠辅助区、保留编辑及任务操作。沿用现有自适应机制，避免再造一套相互冲突的断点规则。
- 如增加全局状态栏，只显示已有可用状态，详细日志留在所属任务中。新增设置追加到类别末尾，新类别追加到列表末尾；实验性入口使用 `Beaker24`，所有图标确认 4.3.0 实际支持。
- 建立仅开发/测试入口可访问的 Showcase，使用真实公共样式和业务组件；展示主题、焦点、禁用、校验、空状态、任务项及翻译行，FlaUI 可操作和截图，不占用正式主导航。

**退出条件：** Smoke、Showcase 交互、明暗与高对比检查通过；公共组件实际截图审查完成；主题切换后编辑、选择、焦点、禁用和错误状态可辨。

## 4. M2：脚本翻译作为首个完整业务试点

主要文件为 `View/Translate/TranslatePage.xaml`、条目组件及对应 ViewModel。保持自由高度的双语条目，减少重复卡片，不把编辑器机械转换为固定行高 DataGrid。

布局分为文件操作区、搜索/类型/状态筛选区、统计与显示选项、主要翻译列表。窄窗口将次要工具折叠；原文、译文、角色及对照层级清楚，译文获得主要空间。保留 ListView 虚拟化并实测容器回收后的编辑状态。

需要完整保留并回归：

- 剧本/译文/参考载入与更换、清除、拖入和导入失败保留当前工作区。
- 普通 TXT 与 TXT-v2、首次保存预检、文件名标签、另存为、覆盖与取消、快捷保存及磁盘结果一致性。
- 未译、明确留空、沿用原文；搜索和类型/状态组合筛选；下一未译/下一提示；隐藏条目不改变导出顺序。
- 角色译名及相同场景文字同步、参考采用、上下文、闪回来源；同步修改整体撤销。
- 黄色参考差异与蓝色载入后修改差异各自的显示开关、载入快照、保存后仍保留载入差异的行为。
- 多行与三行限制、自动规范的焦点时机、换行标记、100%～200% 文本缩放、Tab 跳到下一条可见正文。
- Ctrl+S、Ctrl+Shift+S、Ctrl+F、Ctrl+Enter、撤销/重做；草稿恢复；退出的保存/不保存/取消分支。
- 原角色语音播放、缓存和错误提示；普通回归使用固定音频，真实网络服务另行测试。

**退出条件：** FlaUI 实际输入并保存，独立解析输出验证内容；筛选后编辑、滚动至离屏条目再编辑、撤销和焦点正常；固定长篇样本测量响应与滚动，和旧界面在相同条件下比较；明暗、空状态、参考对照和保存弹窗完成截图复核。输入法组合输入另列真实桌面人工验收。

## 5. M3：自动轴机与字幕复核工作区

左侧保留等待、处理、结束和历史分组；右侧依次容纳素材概要、处理预览、对话/横幅/角标结果和时间轴。任务栏可调宽，时间轴可折叠/调高，预览保持画面比例，短窗口优先保证结果编辑空间。

回归必须围绕现有规则：

- 常规视频+剧本+翻译的素材预检，添加任务模态窗、等待任务拖动排序、顺序推进、任务选择及独立状态。
- 处理时预览、进度、取消、部分完成与未识别原因；至少一项有效帧集合才允许导出。
- 对话、横幅、角标结果复核，已有时间编辑、撤销/恢复和 ASS 导出选项；输出覆盖取消不清除进度。
- 历史按需读取，点击“加载”才恢复完整结果；加载历史不自动执行识别。
- **一次性恢复**使用独立 checkpoint 副本测试：提示前磁盘记录已消费；放弃后不再提示；恢复任务不再写恢复检查点；已完成历史不受影响。禁止把旧记忆中的多次续跑语义当作当前规则。
- 时间轴播放、定位、区间播放、拖动光标不修改字幕时序，以及识别只读态。自定义绘制的光标/手柄需专门检查 UIA；必要时补 AutomationPeer 或等效键盘操作，拖动测试依据实际元素边界，不能依赖固定屏幕坐标。
- 纯视频实验模式单独覆盖视频选择、区间检测、手填翻译、预览与 ASS 导出；清楚呈现无剧本模式的限制，不把普通任务恢复用例直接套入。

**退出条件：** 固定短素材完整跑通识别→复核→导出，检查 ASS 事件与关键时序；关闭期间保存/退出无残留；常规与实验模式分别报告。长视频识别准确率与性能变化不由 UI 回归代替验收。

## 6. M4：视频压制任务监控

复用现有串行队列、任务详情、编码参数模型及 FFmpeg/VapourSynth 管线。按任务概要、进度/阶段、常用操作和可折叠高级详情组织；FFmpeg 参数进入高级区域，完整日志保留独立滚动和“跟随最新日志”。

保留并测试添加/拖入素材、同名 ASS 提示、后台视频分析、常用画质/速度及高级 CRF/线程参数、偏好记忆、等待项编辑锁、顺序执行、取消、重试、结束筛选及错误摘要。覆盖输出冲突与授权、临时盘空间不足、资源不可用等已有失败反馈。

进度复用真实阶段、FPS、ETA、耗时与大小。未形成估算样本时保留未知状态，不为视觉统一显示虚假数值。日志搜索、专用复制及高亮若实施，作为独立新增交互提交并补测。

普通回归使用可控状态数据检查显示；另设真实小任务验证输入→管线→输出可读取、取消后进程退出。前者不作为编码集成测试通过证据。

**退出条件：** 页面功能与截图验收通过；小素材真实编码与取消通过；缺少 VapourSynth/原生资源时报告具体缺口，不用模拟结果替代。

## 7. M5：数据下载资源浏览器

保留数据源、当前类别搜索与筛选、五类专有列表和下载任务区。统一顶部工具栏，支持辅助队列折叠/调宽；各类别仍使用适合其数据的卡片或列表，不强制统一网格切换。

回归覆盖主线章节、活动与章节、特殊剧情、角色卡片及地图对话；地图对话保留活动关联和缺失信息降级。数据源切换后结果和缓存状态正确，不串用前一来源；刷新当前列表、清除缓存、空结果和失败提示清楚。

固定 fixture 服务覆盖搜索、选择/批量操作、加入队列、受控下载、取消、失败及现有重试入口（按源码提供的能力落用例），校验落盘剧本内容。保存目录配置与打开文件夹入口一致，改变下载目录不迁移已有文件。可验证下载后前往翻译的既有衔接，不增加新的跨页协议。

**退出条件：** 五类各至少一个有效数据场景，另有空/缺失元数据/网络失败场景；外部网络关闭仍可重复跑完确定性功能测试。

## 8. M6：设置与关于

保留 `settings-ui.json` → `SettingCatalog` → `SettingViewBuilder` 的动态生成链，统一标签、编辑器和卡片对齐，为内容设置合理最大宽度；不手写一套替代配置页。设置类别、已有项相对顺序、末尾开发者开关和隐藏空类别的行为均保留。

回归普通项自动保存、还原范围、主题、代理、下载目录、翻译换行标记、轴机参数及实验项。开发者模式独立覆盖开关、服务启动/停止、连接信息、令牌脱敏、阈值保存和非法值反馈；测试采用独立端口和配置，避免截图/树日志泄露令牌。

关于、更新和运行日志入口保留；离线普通回归只验证可控结果，真实升级流程属于独立集成验收。

**退出条件：** 生成器中每种实际编辑器具有稳定 ID 和可用 UIA Pattern；修改后跨进程重载一致；明暗、高对比与开发者显隐不破坏布局或顺序。

## 9. 自动化契约、报告及视觉验收

### 稳定 AutomationId

采用 `MainWindow.Navigation.Subtitle`、`Translation.SaveButton`、`Subtitle.ExportButton`、`Encoding.LogViewer` 等与显示语言无关的 ID。动态设置使用属性键；导航项在 C# 创建处赋值，不能只补 XAML。

动态翻译行使用剧本身份与原始事件身份的复合键；没有原生 ID 时建立会话内稳定映射，明确跨加载边界。任务使用实际任务身份，下载条目使用类别/来源和业务 ID，不使用当前筛选索引、正文或随机视觉截图名。允许业务 ID 参与动态标识，但不能依赖可变的展示文本。

Catalog 记录页面、ID、类型、Pattern、动态策略和对应测试。唯一性限定于同一定位根/场景；重复业务控件通过父级任务/行身份区分。扫描结合源码、动态生成器和运行 UIA 树，覆盖展开、弹窗、离屏滚动及容器复用。

### 测试分层与产物

沿用 xUnit `[Trait("Category", "Smoke" / "Functional" / "Visual")]`；每例另有 TestId 和页面标签。公共等待使用有界条件轮询，动态弹窗重新获取元素；失败先诊断，禁止自动重启掩盖首次失败。

运行产物统一在 `.codex-build/fluent-workbench/artifacts/{RunId}/`，保存 TRX、结构化步骤报告、原图、UIA 树、相关应用日志、环境与清理结果；基准图采用独立受版本管理的目录，只有明确审查通过后才更新。报告区分通过、失败、环境不满足、未执行和视觉待复核。

视觉场景按实际页面覆盖默认、正常数据、选择、关键交互、弹窗、空状态；不适用场景标注原因。双主题之外保留高对比抽查。窗口目标 1280×720、1280×960、1920×1080，并加现有最小窗口 960×600 的可操作性检查；区分 DIP 与截图像素。

100%/125%/150% 使用真实 Windows 缩放会话，记录实际工作区及截图边界，屏幕不足时标为未执行。固定数据、滚动位置与视频帧；对时间、进度、光标等动态区域采用明确遮罩/容差。输出原图、基准、差异图及差异比例，再人工检查截断、溢出、对齐、焦点和状态。无基准时只能报告采集完成，不能报告视觉回归通过。

### 计划中的运行入口

新增 `Tools/RunUITests.ps1`，提供 Smoke、Functional、Visual、CaptureOnly、All 和页面选择。以下是完成 M0 后的目标命令，当前尚不可直接作为已有能力使用：

```powershell
dotnet build SekaiTools.sln
dotnet test .\SekaiTools.Tests\SekaiTools.Tests.csproj
dotnet test .\SekaiTools.UITests\SekaiTools.UITests.csproj --filter "Category=Smoke"
dotnet test .\SekaiTools.UITests\SekaiTools.UITests.csproj --filter "Category=Functional"
dotnet test .\SekaiTools.UITests\SekaiTools.UITests.csproj --filter "FullyQualifiedName~TranslationEditorTests"
dotnet test .\SekaiTools.UITests\SekaiTools.UITests.csproj --filter "Category=Visual"
```

每次页面修改固定执行：改前基线 → 设计 → 实现 → 构建 → Smoke → 当前页 Functional → 截图审查 → 修复 → 相关回归。涉及 C# 时按仓库要求格式化并验证。测试脚本失败、UI 缺陷与业务缺陷分别归因，不能以删除断言、关闭真实交互或降低标准消除失败。
