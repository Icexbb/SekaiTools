# 翻译 TXT 格式 v2

状态：已实现 v2 加载和导出，兼容旧 TXT 加载与导出；保存选项默认选择 v2。

## 目的与匹配依据

保留翻译人员使用记事本临时修改 TXT 的能力，同时避免删除、插入文本行或调整条目顺序造成后续翻译错位。

剧本由外部提供，同一 `ScenarioId` 的内容固定不变。使用 JSON 内部的 `ScenarioId` 识别剧本，不依赖剧本或翻译文件名，不增加版本修订摘要或原文指纹。

条目通过“ScenarioId＋条目类型＋编号”对应原剧本，而不是通过翻译文件中的排列位置对应。

## 文件与示例

文件扩展名为 `.txt`，编码为 UTF-8。接受 Windows CRLF 和 LF 换行。

```txt
@version:2
@scenario:aprilfool_2024_01

# 修改方括号内的说话人和下面的正文，保留条目标记与编号。
@dialog:001[初音未来]
下面是内容
这里是第二行内容

@banner:001
Sekai的夹缝

@marker:005
学校
```

示例用于说明语法；条目及编号应由对应剧本生成，不代表范例剧本的完整内容。

## 固定标签

所有结构标记以行首 `@` 开头，标签使用下表中的小写拼写。冒号为半角 `:`，方括号为半角 `[]`。允许标记行末尾存在空格或制表符。

| 标签语法 | 含义与约束 |
| --- | --- |
| `@version:2` | 格式版本，文件第一条有效行，必须出现且只能出现一次。 |
| `@scenario:<ScenarioId>` | 剧本内部标识，位于版本行之后、第一条翻译之前，必须出现且只能出现一次；值必须与所载入剧本的 `ScenarioId` 一致。 |
| `@dialog:<编号>[<说话人>]` | 对话条目。说话人直接写在方括号内，正文从下一行开始。 |
| `@banner:<编号>` | 横幅条目，正文从下一行开始，对应 `EffectType = 8`。 |
| `@marker:<编号>` | 地点角标条目，正文从下一行开始，对应 `EffectType = 18`。 |

本版本不使用 `@end`、`@speaker`、`@text`、`@revision`、`@source` 或其他标签。未知标签必须报错。

### 编号

- 编号是原始 JSON 数组的零基下标加一，以十进制表示，导出时至少补齐三位，例如 `001`、`025`、`1000`。
- `@dialog` 对应原始 `TalkData` 数组。
- `@banner` 与 `@marker` 均对应原始、未过滤的 `SpecialEffectData` 数组；不能按程序筛选后的效果列表重新编号。
- 因原数组可能包含其他效果类型，横幅和角标的编号允许不连续。
- 编号按数值识别，`001` 和 `1` 表示同一编号；不允许零、负数或非数字。
- 不同类型可以使用相同编号，同一类型的编号不得重复。
- 移动整个条目不会改变其对应关系，不得根据翻译文件中的出现顺序重新编号。

### 说话人

`@dialog:001[初音未来]` 中的说话人与正文由标记结构分开，不再使用正文中的任何冒号拆分两者。正文里的半角或全角冒号均为普通内容。

以编号后的第一个 `[` 和标记行末最后一个 `]` 包围说话人，中间内容全部作为名称，因此名称内允许包含方括号。允许空说话人，例如 `@dialog:001[]`。说话人占一行，不支持在名称中换行。横幅与角标不包含说话人字段。

## 正文、空行与注释

- 条目标记下一行开始为正文，持续到下一个结构标记或文件末尾，不需要结束标签。
- 一个条目可以有多行正文，保留正文内部的换行和空行。
- 去掉每个条目正文首尾的空行（包括仅含空格或制表符的行），方便在条目之间留空行；不支持用这些空行表达正文开头或结尾的留白。
- 导入和导出时先将 CRLF、LF（也接受单独 CR）统一为 LF，再对每一行分别执行 `Trim()`，最后以 LF 合并；去掉条目首尾空行，保留内部空行及行内空格，不自动拆分冒号或替换省略号。
- 对话与效果正文均应用上述规则，旧格式正文的 `\N` 在加载时统一转换为 LF，导出时转换回 `\N`；v2 中的字面量 `\N` 保持原样。重复导入导出不会因 CRLF 被拆成两次换行而增加空行。编辑器已有的标点规范化行为仍然适用。
- 允许空正文，表示显式空翻译。空正文不等于缺失条目，也不得用后一条内容补位。
- 行首 `#` 开头的整行是注释，可放在文件头或条目之间、正文之中；读取时忽略，不产生正文空行。不支持行尾注释，正文中间的 `#` 为普通字符。
- 结构标记及注释应从第一列开始，不允许通过缩进表示结构标记。
- 第一条翻译之前，除文件头标记、注释与空行外，不允许出现普通正文。

### 正文中的特殊行首字符

正文行确实以 `@` 或 `#` 开头时，分别写成 `\@`、`\#`，读取时去掉转义反斜杠。为使该规则可逆，以反斜杠开头的正文行写成两个反斜杠开头，读取时还原一个。其他位置的反斜杠保持原样，不将字面量 `\n` 解释成换行。

```txt
@dialog:001[初音未来]
\@这里是正文，不是标记
\#这里是正文，不是注释
\\这里的正文以一个反斜杠开头
正文里可以直接写：时间是12:30。
```

## 导入校验

导入新版文件必须先解析、校验，再应用到剧本。不得在失败时按顺序套用部分翻译。

以下情况需要明确提示原因；能够定位时附上翻译文件行号、标签或编号：

- 缺失、重复或不支持的格式版本；缺失或重复的 `@scenario`。
- `ScenarioId` 与所载入剧本不一致，或剧本缺少可用的 `ScenarioId`。
- 未知标签、错误的标记语法、缺少说话人方括号等。
- 同类型重复编号、编号越界或编号格式不合法。
- 类型不匹配，例如 `@banner` 指向的原始效果不是 `EffectType = 8`。
- 缺失剧本要求的对话、横幅或角标条目；非字幕效果不要求翻译条目。
- 头部位置不合法，或第一条翻译之前出现无归属正文。

条目顺序改变、正文包含冒号、多行正文、空说话人和显式空正文均不是格式错误。

## 旧格式兼容与实现范围

保留旧 TXT 的导入能力。旧格式仍按其原有规则解析：按行顺序对应剧本，使用全角冒号区分说话人与正文。该拆分规则仅适用于旧格式，不能用于 v2。

新版文件以 `@version:2` 声明格式，保存时使用本文规定的规范写法。包含新版版本声明但语法错误或版本不支持时，应报告新版格式错误，不得退回旧格式解析来掩盖问题。

程序保留 `GameScript.ScenarioId`，在筛选 `SpecialEffectData` 前记录原始数组下标。普通翻译、参考翻译与字幕任务共用格式识别及校验。保存选项提供“TXT v2”和“旧 TXT”，默认选择 v2；缺少 `ScenarioId` 的旧剧本可继续选择旧格式导出。
