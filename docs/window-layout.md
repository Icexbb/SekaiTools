# 小窗口与 DPI 适配

## 尺寸与布局规则

- 主窗口默认尺寸为 1280×960 DIP，通常允许缩小至 960×600 DIP。DIP 是 WPF 的逻辑单位，不等于显示器物理像素。
- `WindowWorkArea` 按窗口所在显示器的工作区和 DPI 调整启动尺寸、最小尺寸和位置。工作区不足 960×600 DIP 时进一步降低窗口下限，避免窗口超出屏幕。
- GUI manifest 开启 Per-Monitor V2 DPI 感知。跨屏、DPI、显示配置、工作区变化及恢复窗口时重新检查窗口边界。
- `AdaptiveLayout.MonitorSize` 根据页面实际可用尺寸提供可继承的断点：宽度小于 1100 DIP 为窄布局，高度小于 700 DIP 为矮布局。
- 字幕页在矮布局下缩小预览，进入矮布局时收起时间轴；用户仍可展开，时间轴独立滚动。事件列表和筛选区保留独立的受限视口。
- 翻译页工具栏保留原有四列布局和常显任务信息，不采用自动换行或折叠；编辑列表继续保留虚拟化。
- 压制页在窄布局使用队列标签页，宽布局保留双栏；切换时移动原有控件，保留数据、命令和拖拽处理。矮布局缩小执行日志的视口。
- XAML 内容弹窗通过 `AdaptiveLayout.FitDialog` 使用 WPF-UI 的 `DialogMaxWidth`、`DialogMaxHeight` 限制正文和按钮区域。已有滚动容器、字体列表及压制任务表单约束正文高度，避免外层再次滚动。

## 验证

常规检查：

```powershell
dotnet build SekaiToolsGUI/SekaiToolsGUI.csproj -c Release
dotnet test SekaiTools.sln -c Release
git diff --check
```

本次使用隔离的 WPF 布局验证程序检查了 1200×850、900×500、780×450 DIP 的字幕页面视口，停止／输出／重置按钮，以及手动展开后的时间轴边界；检查了队列双栏与标签页的反复切换、设置页面和 900×500 DIP 宿主中的保存／压制／字体弹窗。保存、压制和字体弹窗的底部操作及外层滚动检查通过。布局验证文件和截图保存在被 Git 忽略的 `artifacts/ui-smoke/`。

发布前仍需在实际显示设备上检查以下场景：

| 场景 | 验收重点 |
| --- | --- |
| 1366×768、1280×720、1024×768，100% 缩放 | 启动窗口完整可见，关键操作可达 |
| 1920×1080，125%／150% 缩放 | 字体正常，小窗口断点按 DIP 生效 |
| 100% 与 150% 缩放的显示器间拖动 | 窗口尺寸、位置和文字随当前 DPI 调整 |
| 最大化、恢复、改变任务栏位置、断开副屏 | 窗口恢复后位于可用工作区 |
| 弹窗打开时缩小／放大主窗口 | 正文视口同步改变，底部按钮保持可见 |
| 有大量字幕、队列任务和执行日志 | 列表及日志局部滚动；队列拖拽排序仍可使用 |
| 矮窗口手动展开时间轴、加载较长翻译文件 | 时间轴控件可通过滚动访问，编辑列表不被整页滚动替代 |
